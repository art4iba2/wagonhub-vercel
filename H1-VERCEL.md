# H1. Ускорит ли пул Psycopg ответ API каталога на Vercel?

## Как устроен эксперимент
Один синхронный ConnectionPool на процесс создаётся при первом обращении к PostgreSQL. Минимум 0 подключений, максимум 4 по умолчанию; простой лишних соединений 60 с, срок жизни до 10 мин, до 32 ожидающих, ожидание до 5 с. Проверка соединения при выдаче добавляет обращение к БД, зато позволяет заменить устаревшее соединение. При переполнении/тайм-ауте получения соединения обычный API возвращает HTTP 503. Проверяется и при успехе, и при неудаче транзакции: соединение возвращается владельцу-пулу через close(). COMMIT/ROLLBACK, проверки вместимости и блокировки строк сохраняются. SQL не кэшируется на уровне приложения; заголовок Cache-Control: no-store одинаков в обоих вариантах. Оба режима используют одинаковые параметры драйвера, включая выключенную автоподготовку SQL. Завершение процесса освобождает соединения; при обычном выходе пул закрывается явно.

## Как измерять (Windows, из корня проекта)
Нужны Python 3.8+ (команда py -3 или python) и curl.exe в PATH. Подставьте реальные базовые адреса, без /api и без завершающего #listings:
```powershell
$direct = 'https://АДРЕС-КОНТРОЛЬНОГО-DEPLOYMENT'
$pooled = 'https://АДРЕС-DEPLOYMENT-С-ПУЛОМ'
py -3 .\bench\measure_h1.py --url $direct --mode direct
py -3 .\bench\measure_h1.py --url $pooled --mode pool
```
Повторите, чередуя порядок (A–B, B–A, A–B). Выполняйте с одного ПК, не одновременно, без изменений в каталоге. Скрипт делает пять прогревочных запросов, затем 100 последовательных измерений. При несовпадении режима прерывается. Печатает p50/p95 успешных ответов и число ошибок, сохраняет каждое измерение в отдельный по умолчанию CSV. Значения — полное время HTTP, включая сеть; выполнение SQL отдельно не измеряется. Прогрев не гарантирует попадание всех запросов на один экземпляр Vercel. Первые запросы после длительного простоя при необходимости исследуйте отдельной серией.
Эффект (%) = 100 × (p95_direct − p95_pool) / p95_direct. Отрицательное значение означает замедление. Сравните парные серии и доли ошибок. Для единого p95 по всем запросам каждого варианта объедините исходные времена успешных ответов из CSV, а не усредняйте процентили. Старый результат 1 304,16 мс — медиана трёх p95 предыдущей версии.

## Локальная проверка кода
Штатный compose.yaml по-прежнему использует SQLite. Для интеграционных тестов нужна отдельная PostgreSQL 17; она поднимается через compose.check.yaml. Команды из корня архива:
```powershell
docker compose -p wagonhub-h1-check -f compose.check.yaml build tests
docker compose -p wagonhub-h1-check -f compose.check.yaml run --rm tests
docker compose -p wagonhub-h1-check -f compose.check.yaml down
```
Отдельно: tests/test_h1_pool.py проверяет реальный менеджер пула с подменой сетевого соединения; tests/test_postgres.py проверяет решение по последнему месту в режимах direct и pool при наличии WAGONHUB_TEST_POSTGRES.
