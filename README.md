# ВагонМесто

Рабочий MVP площадки аренды вагоно-мест по приложенному ТЗ. Интерфейс на русском языке, API на FastAPI. Локально используется SQLite, на Vercel — PostgreSQL в Neon или другом внешнем сервисе.

## Лендинг и Яндекс Метрика

По адресу `/` открывается лендинг. Кнопки ведут в каталог, регистрацию и личный кабинет. Интерфейс работает и без счётчика. Чтобы включить аналитику, создайте счётчик в [Яндекс Метрике](https://metrika.yandex.ru/) и добавьте его числовой ID в переменную окружения `YANDEX_METRIKA_ID` на Vercel (**Settings → Environment Variables**, Production и при необходимости Preview). Сделайте Redeploy. Для Docker задайте `YANDEX_METRIKA_ID=12345678 docker compose up --build -d` (подставьте ваш ID). ID счётчика публичен; строку подключения к базе сюда не добавляйте.

После согласия посетителя загружается скрипт Метрики. До согласия никаких запросов к Метрике нет. Посетитель может отказаться или изменить выбор через «Настройки аналитики» внизу сайта. Включены карта кликов и учёт смены разделов (`#home`, `#listings` и другие); Вебвизор выключен. Приложение не передаёт в события имена, email, ИНН, номер заявки или ID объявления.

Для отчёта по кнопкам создайте в интерфейсе Метрики цели типа **«Целевое событие»** с идентификаторами ниже. Каждое нажатие на две кнопки перехода в каталог с лендинга учитывается в общей цели `landing_find_places`.

| Цель | Событие |
| --- | --- |
| `landing_find_places` | Переход с лендинга в каталог |
| `landing_register_track`, `landing_register_wagon` | Регистрация с лендинга для владельца пути или вагонов |
| `open_catalog`, `open_account`, `open_create_listing`, `open_login` | Переходы из навигации |
| `filters_submit`, `clear_filters` | Применение и сброс фильтров |
| `request_click`, `request_login_click` | Клик по кнопке заявки или входа для отклика |
| `request_sent` | Заявка успешно создана |
| `registration_success`, `login_success`, `company_created` | Успешное действие после ответа сервера |
| `listing_created`, `edit_listing_click`, `listing_updated` | Публикация и редактирование объявления |
| `listing_withdrawn`, `request_confirmed`, `request_rejected` | Снятие объявления и решения по заявке |

Чтобы сравнить кнопки, откройте в Метрике **Отчёты → Конверсии** и сопоставьте достижения целей. События появляются лишь после добавления целей и согласия посетителя. Проверьте работу на своём сайте через режим проверки целей Метрики. При некорректном ID сайт остаётся доступным, а аналитика отключается; проверьте журнал запуска и укажите только цифры.

## Быстрый запуск через Docker

Нужны Docker и Docker Compose. В корне проекта выполните:

```bash
docker compose up --build -d
```

Откройте **http://localhost:8000**. Документация API: **http://localhost:8000/docs**. Для просмотра журналов используйте `docker compose logs -f web`, для остановки — `docker compose down`. Именованный том `wagonhub_data` сохраняет базу при обычной остановке. Команда `docker compose down -v` удаляет том и данные.

## Запуск без Docker

Нужен Python **3.14**. В корне проекта:

```bash
python3.14 -m venv .venv
. .venv/bin/activate
pip install -e '.[test]'
uvicorn wagonhub.app:app --reload
```

Откройте **http://127.0.0.1:8000**. По умолчанию база создается в `./wagonhub.db`. Для другого расположения установите абсолютный путь в `DATABASE_PATH` или каталог в `DATA_DIR` перед запуском. Эти переменные задавайте до импорта приложения. Держите файл базы в каталоге с правами записи для процесса сервера.

## Как пользоваться

1. Зарегистрируйтесь как **владелец путей** и создайте объявление: название, город, адрес, вместимость, стоимость за вагон и описание. Объявление видно в общем списке. В личном кабинете его можно изменить или снять.
2. Зарегистрируйте второй аккаунт как **владелец вагонов**. Создайте компанию с названием, ИНН и email.
3. Откройте объявления, задайте город, минимальное количество свободных мест и максимальную цену. Укажите число вагонов и отправьте заявку.
4. Владелец пути видит в заявке имя и email отправителя, название и ИНН компании, рабочий email и телефон (если указан). Он подтверждает или отклоняет заявку в личном кабинете. Подтвержденные вагоны занимают места, а сделка отображается в истории обеих сторон. Если свободных мест стало меньше, подтверждение лишней заявки блокируется.

Заявка фиксирует цену за вагон на момент ее создания: последующее изменение объявления не меняет цену в существующей заявке. Нельзя уменьшить вместимость ниже числа занятых мест. Когда вагоны покинут площадку, владелец пути завершает размещение, и места снова появляются в каталоге. Подтвержденная сделка остается в истории после снятия объявления, а ожидающие заявки на него отклоняются. Для роли пользователя создается отдельный аккаунт; роль после регистрации не меняется. Яндекс Карты обозначены в ТЗ как возможное расширение и не подключены в этом MVP.

## Тесты

```bash
pytest
```

Конфигурация требует не менее **90% покрытия** Python кода. Сценарии проверяют регистрацию, роли, компании, фильтры, редактирование и снятие объявлений, контактные данные заявителя, историю и конкурирующие заявки по вместимости. Обычный запуск тестов использует SQLite и заглушку PostgreSQL. Для проверки реальной PostgreSQL и одновременного подтверждения последнего места используйте отдельный Docker Compose ниже.

## Структура

- `wagonhub/app.py` — маршруты API, проверка доступа, операции с объявлениями и сделками.
- `wagonhub/db.py` — схемы SQLite/PostgreSQL и транзакции.
- `wagonhub/schemas.py` — Pydantic модели и ограничения входных данных.
- `wagonhub/static/` — интерфейс на HTML, CSS и JavaScript.
- `tests/` — API тесты с изолированной базой.

Сеансы хранятся в базе в виде хэшей токенов и действуют семь дней. Пароли хранятся как PBKDF2 хэши с индивидуальной солью. Вход и регистрация ограничены по числу попыток. Для публикации настройте HTTPS и резервное копирование базы.

GitHub Pages может разместить только статический интерфейс; для FastAPI нужен сервер или Vercel Functions с внешней базой данных.

## Пилот по приглашениям

Отдельная проверка с настоящим PostgreSQL, двумя одновременными подтверждениями
одного места и повторной инициализацией приложения:

```bash
docker compose -p wagonhub-check -f compose.check.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -p wagonhub-check -f compose.check.yaml down
```
## Админка и ссылки на регистрацию

1. В Vercel, в **Settings → Environment Variables → Production**, задайте
   `PILOT_ADMIN_EMAILS` — список email через запятую, например
   `owner@example.com, colleague@example.com`. Включите в список свой прежний
   адрес, если хотите сохранить доступ. Непустой список заменяет одиночное
   значение `PILOT_ADMIN_EMAIL`. При отсутствии списка действует прежняя
   переменная. Для локального Docker те же настройки можно задать в `.env`.
2. Для новых аккаунтов добавьте каждый адрес в `PILOT_INVITES_JSON`,
   сохранив остальные записи. Пример записи:
   `"owner@example.com":{"role":"track","code":"REPLACE_WITH_A_PRIVATE_RANDOM_CODE"}`.
   Сгенерируйте отдельный код для каждого:
   `py -c "import secrets; print(secrets.token_urlsafe(32))"`
   (или используйте `python` вместо `py`). Если аккаунт уже зарегистрирован,
   он должен уже иметь доступ к пилоту — через принятый инвайт из админки либо
   через запись в `PILOT_INVITES_JSON` с его текущей ролью.
3. Разверните новую версию, затем войдите в `/admin` под своим аккаунтом.
   Если аккаунта ещё нет, сначала зарегистрируйтесь с кодом из пункта 2.
   Каждый администратор входит под своим email и паролем и может управлять
   приглашениями. Чтобы снять права у одного человека, удалите его адрес
   из списка и сделайте Redeploy; это не удаляет аккаунт и не снимает его
   обычный доступ к пилоту. Для полного отключения админки удалите обе
   переменные. На Vercel по-прежнему нужен `DATABASE_URL`.
4. В админке введите email и выберите роль; для владельца вагонов
   укажите ИНН. Нажмите **«Создать приглашение» → «Скопировать ссылку»**
   и отправьте её участнику вручную. Участник открывает ссылку, вводит
   приглашённый email и задаёт пароль. Для приглашённых через админку
   редактировать `PILOT_INVITES_JSON` и делать Redeploy не нужно.

Ссылка действует 7 дней, рассчитана на одну регистрацию и отображается
сразу после создания. Если её потеряли, отзовите приглашение и создайте новое.
Отзыв доступен только до регистрации и не блокирует уже созданный аккаунт.
Старые приглашения из `PILOT_INVITES_JSON` работают по прежней схеме и не
отображаются в истории приглашений админки.

Не добавляйте реальные коды, `.env` и строку подключения в Git.

## Восстановление пароля по email (Unisender Go)

В форме входа появится ссылка **«Забыли пароль?»**. Введите email существующего
аккаунта, подтвердите 8-значный код из письма и задайте новый пароль.
Пароль меняется у того же аккаунта: роли, объявления и заявки сохраняются.
Это работает и для мастер-аккаунта, если он допущен к пилоту.
После смены пароля все его прежние сеансы завершаются.

### Подключение на Vercel

1. Откройте [Unisender Go](https://go.unisender.ru/). В меню
   **Настройки → Домены отправки** добавьте `wagonhub.ru`, подтвердите владение
   и внесите DNS-записи из кабинета сервиса. См. [инструкцию по DNS](https://godocs.unisender.ru/dns-setup).
   Сохраните текущие записи сайта для Vercel. Проверьте SPF и DKIM в кабинете Go.
2. Возьмите API-ключ **Unisender Go** в настройках либо создайте ключ для проекта.
   Настройте отправителя с подтверждённого домена, например `no-reply@wagonhub.ru`.
3. В **Vercel → Settings → Environment Variables**, окружение **Production**,
   добавьте переменные:

   | Имя | Значение |
   | --- | --- |
   | `UNISENDER_GO_API_KEY` | API-ключ Go, тип **Secret** |
   | `RESET_FROM_EMAIL` | Подтверждённый адрес отправителя |
   | `PASSWORD_RESET_SECRET` | Отдельный случайный секрет, тип **Secret** |

   Секрет создайте командой PowerShell:
   `py -c "import secrets; print(secrets.token_urlsafe(48))"`.
   Не используйте тот же секрет для Preview или локальной среды. Не кладите
   реальные ключи или `.env` в Git.
4. Выполните Redeploy. Если нет хотя бы одной из этих настроек, кнопка
   восстановления скрыта и API не отправляет письма. Для локального запуска
   Docker значения можно задать в `.env` (рядом с `compose.yaml`).
5. Откройте `/reset-password` на опубликованном сайте. Проверьте получение кода
   на доступных вам ящиках, например Яндекс Почта и Mail.ru, и вход с новым паролем.
   Если письмо не пришло, проверьте спам, историю отправок Go и журналы Vercel.
   Сообщение на сайте намеренно одинаковое для существующего и неизвестного email.

Код действует 10 минут и допускает до 5 ошибочных попыток. Повторное письмо
запрашивается не чаще раза в минуту; действующий старый код заменяется.
Подтверждённый код выдаёт одноразовое разрешение на смену пароля на 10 минут.
В браузер не передаются API-ключ и серверный секрет; Метрика на странице
восстановления отключена. Тесты имитируют почтовый транспорт и не отправляют
письма внешним получателям.
