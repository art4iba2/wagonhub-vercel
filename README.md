
## Быстрый запуск через Docker

Нужны Docker и Docker Compose. В корне проекта выполните:

```bash
docker compose up --build -d
```

Откройте **http://localhost:8000**. Документация API: **http://localhost:8000/docs**. Для просмотра журналов используйте `docker compose logs -f web`, для остановки — `docker compose down`. Именованный том `wagonhub_data` сохраняет базу при обычной остановке. Команда `docker compose down -v` удаляет том и данные.

## Запуск без Docker

Нужен Python **3.14**. В корне проекта:

```bash
python3.14 -m venv .venv
. .venv/bin/activate
pip install -e '.[test]'
uvicorn wagonhub.app:app --reload
```

Откройте **http://127.0.0.1:8000**. По умолчанию база создается в `./wagonhub.db`. Для другого расположения установите абсолютный путь в `DATABASE_PATH` или каталог в `DATA_DIR` перед запуском. Эти переменные задавайте до импорта приложения. Держите файл базы в каталоге с правами записи для процесса сервера.

## Как пользоваться

1. Зарегистрируйтесь как **владелец путей** и создайте объявление: название, город, адрес, вместимость, стоимость за вагон и описание. Объявление видно в общем списке. В личном кабинете его можно изменить или снять.
2. Зарегистрируйте второй аккаунт как **владелец вагонов**. Создайте компанию с названием, ИНН и email.
3. Откройте объявления, задайте город, минимальное количество свободных мест и максимальную цену. Укажите число вагонов и отправьте заявку.
4. Владелец пути видит в заявке имя и email отправителя, название и ИНН компании, рабочий email и телефон (если указан). Он подтверждает или отклоняет заявку в личном кабинете. Подтвержденные вагоны занимают места, а сделка отображается в истории обеих сторон. Если свободных мест стало меньше, подтверждение лишней заявки блокируется.

Заявка фиксирует цену за вагон на момент ее создания: последующее изменение объявления не меняет цену в существующей заявке. Нельзя уменьшить вместимость ниже числа мест в подтверждённых сделках. Снятое объявление можно изменить, но оно остаётся снятым. Оплата и договорный документооборот не реализованы: в ТЗ они не описаны. Подтвержденная сделка остается в истории после снятия объявления, а ожидающие заявки на него отклоняются. Для роли пользователя создается отдельный аккаунт; роль после регистрации не меняется. Яндекс Карты обозначены в ТЗ как возможное расширение и не подключены в этом MVP.

## Тесты

```bash
pytest
```

Конфигурация требует не менее **90% покрытия** Python кода. Сценарии проверяют регистрацию, роли, компании, фильтры, редактирование и снятие объявлений, контактные данные заявителя, историю и конкурирующие заявки по вместимости. Тесты PostgreSQL адаптера используют имитацию соединения; дополнительно проверьте подключение к вашей базе на тестовом развёртывании. В этой среде доступен Python 3.12; Vercel и Docker настроены на Python 3.14.

## Структура

- `wagonhub/app.py` — маршруты API, проверка доступа, операции с объявлениями и сделками.
- `wagonhub/db.py` — схемы SQLite/PostgreSQL и транзакции.
- `wagonhub/schemas.py` — Pydantic модели и ограничения входных данных.
- `wagonhub/static/` — интерфейс на HTML, CSS и JavaScript.
- `tests/` — API тесты с изолированной базой.

Сеансы хранятся в базе в виде хэшей токенов и действуют семь дней. Пароли хранятся как PBKDF2 хэши с индивидуальной солью. Для публичного размещения добавьте HTTPS, резервное копирование базы и ограничения частоты запросов на вход и регистрацию.

GitHub Pages может разместить только статический интерфейс; для FastAPI нужен сервер или Vercel Functions с внешней базой данных.
